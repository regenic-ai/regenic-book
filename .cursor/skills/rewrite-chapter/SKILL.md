# 重写章节

## 目标

把一段书稿重新讲清楚，而不是把旧句换几个词。读者应能顺着读下去，复述这一段的判断，并查到其中的事实。

这条 skill 只负责中文书稿的重写。它不改变全书理论，也不替用户决定尚未验证的事实。

## 先看哪些文件

开始前读相关内容，并按下面的优先级处理冲突：

1. `outline.md`：全书主张、概念名称和章节关系。
2. `content/zh/standards/book-standard.md`：一章要交付什么。
3. `content/zh/standards/prose-standard.md`：读者正文怎样写得清楚、自然。
4. `content/zh/standards/chapter-template.md`：动笔前的一页纸。

这条 skill 只把这些规则变成步骤，不能新增理论、改动固定概念，或用自己的比喻替换大纲中的工作语言。

如果大纲本身有矛盾、证据不足以支持论断，或用户要求改动全书主张，先说明问题并回到大纲或研究，不在正文里偷偷补。

大纲里的三级工具词只在所属章节内使用。没有更新大纲，不把它们抬成全书的新框架。

## 范围

- 默认只改 `content/zh/` 中读者可见的章节正文。
- 不顺手改英文稿。只有用户明确要求翻译或中英文术语需要同步时，才单独处理英文。
- 不把状态行、研究笔记、事实卡或验收表写进正文。
- 不编造数字、案例、引文、经历或出处。

## 四步工作法

### 1. 先写本章地图

重写整章时，先用简短的工作稿回答：

- 本章在全书里解决什么问题；
- 它从上一章接到什么，交给下一章什么；
- 本章的一句话论断；
- 需要回应的反例或读者疑问；
- 已有案例和仍缺的证据。

把这些内容填入 `chapter-template.md` 的对应栏位。地图和一页纸是同一阶段的两种视图：前者帮助讲清因果，后者检查框架、案例和行动是否齐全；不把它们设成两道重复闸门。

只改一节时，不必重做整张地图，但要读该章论断和前后两节，确认这一节在推进什么。

如果大纲的节数或顺序与现有章节文件不一致，先停下来说明差异。由用户决定更新大纲还是调整章节结构；不要悄悄选一边继续写。

### 2. 把事实和旧句分开

为每一节列一张事实卡：

```markdown
## 事实卡（第 X 章第 X 节）
- 本节的一句大白话：
- 必须保住的概念名：
- 必须保住的数字、名字、出处：
- 案例及其可说和不可说的部分：
- 仍缺的案例、数据或出处：
- 与前后节的衔接：
```

旧稿可以用来核对事实，不能用来决定新稿的句式。先把可核验的信息摘出来，再离开旧稿写作；缺少来源的细节宁可不写，也不要补想象。赢家或输家缺一侧时，明确标记为证据缺口：可以继续写草稿，但不能把这一章标成完稿。

### 3. 从大白话重新写

根据大纲、事实卡和前后文，从头写这一节：

- 先把因果讲清，再给概念命名；
- 用书里锁定的概念，不为躲相似度另造“价签、圈、坡”一类新道具；
- 让事实服务于判断，不把案例名单当成论证；
- 按 `prose-standard.md` 检查主语、连接词、比喻和口号；
- 写完出声读一遍。卡住的地方整句或整段重写，不靠删词硬压短。

默认直接推进到完整草稿。只有遇到必须由用户决定的事项时才暂停：例如改变核心论断、选择相互冲突的事实来源，或重排章节骨架。

### 4. 先核对，再判断是否真的重写

完成草稿后，按顺序检查：

1. **事实**：数字、名字、条件、出处和案例结论是否准确。
2. **论证**：是否仍在讲大纲里的那句话，前后节是否接得上。
3. **文风**：是否通过 prose standard 的八项自检。
4. **相似度**：当旧稿与新稿可比较时，运行：

```bash
python3 .cursor/skills/rewrite-chapter/scripts/similarity.py 原稿文件 新稿文件
```

相似度只用来发现逐句换词。若超过一半的可计入句子与旧稿相似，回到第 3 步，改叙述顺序、主语和段落结构；不要为了通过脚本生造术语。数字和专有名词相似是正常情况，应人工判断。

章节达到大纲的篇幅目标之前，不把字数当填充任务。若论证还薄，写清缺的是案例、机制、数据还是行动清单；若证据未齐，保持“展开中”，不标“完稿”。

## 交付格式

一次重写至少交付：

1. 读者可直接阅读的完整新稿；
2. 这一节或这一章的一句大白话；
3. 本次重写的深度：整句、整段或整节；
4. 保住了哪些关键事实，以及仍待补的证据。

不要只交一串替换建议，也不要把工作过程、检查表或“作者旁白”混进正文。

## 什么时候不用这条 skill

- 只改错别字、标点或链接：直接修改。
- 修改 `outline.md`、公开标准或概念命名：先处理对应的标准文件，不按章节重写流程走。
- 只翻译英文：使用翻译流程，并单独核对术语。

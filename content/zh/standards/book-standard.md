# 本书公开标准

> 这份标准说明《重写基因》要交付什么，也让贡献者和读者知道如何判断一章是否站得住。编辑讨论和变更流水留在内部，不放进公开仓库。

## 先看哪份文件

几份写作文件各管一件事，不能互相改写职责：

1. `outline.md` 定全书主张、概念名称和章节之间的关系，是论点的唯一来源。
2. 本文件定一本书和一章书要交付什么。
3. `prose-standard.md` 只管读者看见的中文正文怎样写得清楚、自然。
4. `chapter-template.md` 是动笔前的工作表。
5. `rewrite-chapter` skill 只把前面四份文件变成操作步骤，不能另起理论或改动概念。

规则冲突时，按这个顺序处理。论点不清，先改大纲；证据不够，先补研究；句子不顺，才改正文。

## 一、一本管理书需要交付什么

本书参考《跨越鸿沟》《创新者的窘境》《从优秀到卓越》《精益创业》《从 0 到 1》和《蓝海战略》等作品的共同做法，但不复制它们的句式。读者至少应从书里带走五样东西：

1. **一个反直觉的核心论断**：能用一句话说明，也允许被事实推翻。
2. **一个可复用的主框架**：读者能画在白板上。本书的框架是“两个统一”——统一判断标准，统一上下文。
3. **不超过五个一级概念**：其中“重写基因 / Regenic”是唯一对外主推的概念；完整分级以 `outline.md` 为准。
4. **能检验论断的案例**：核心论断要同时寻找赢家和输家，每章至少有一组外部对照；缺哪一侧，要明确写出来。
5. **一套可执行的行动手册**：读者周一早上就能开始做。本书对应第 14 章的 90 天手册。

**主读者**：对结果负责的一号位，包括创始人、CEO 和事业部负责人。

**三个载体的关系**：《重写基因》是目前最完整的公开论述；Regenic.ai 持续更新方法；bioby.ai 是第一个实验场，不是方法论官网。

**Regenic 能做和不能做的事**：它帮助企业识别限制性资源、提炼标准、确定验收口径并组织第一轮验证；它不替一号位做判断，不代写脱离现场的标准，也不承诺把转型外包出去。

## 二、公开命名

- 主书名：**《重写基因》/ Regenic**
- 副标题：**如何构建 AI 原生组织 / How to Build an AI-Native Organization**
- 「最后的稀缺」是问题的名字，也是前言和第二部的标题；它属于书内二级概念，不参与一级概念的对外传播。

书名评分和市场测试细节属于内部编辑资料，不在公开仓库维护。

## 三、一章写完，至少要留下什么

每章完稿必须同时满足以下条件：

1. 能说清它在全书中解决什么问题、从上一章接到什么、交给下一章什么（见 `chapter-template.md`）。
2. 论断能用一句话复述，并且是全书核心论断往前推的一步。
3. 有一张能画在白板上的框架图。
4. 至少有一组外部赢家/输家对照和可引用的数据。只有两侧各自拥有多个、口径可比的观察值时，才分别报告中位数；每侧只有一个案例时，直接报告原始事实与样本量，并明确它不能估计典型效果。案例若只用于识别机制或行为边界，就不得冒充经营结果的因果对照。缺少其中一侧时，可以继续做草稿，但必须标为证据缺口，不能标为完稿。
5. 留下至少三句值得测试的金句候选，记在 `notes/worklog.md`，不强行塞进正文。
6. 结尾给出“周一早上怎么做”的动作清单。
7. 正文通过 [`prose-standard.md`](./prose-standard.md) 的验收：意思准确，因果讲清，读起来像人话；重写以整句和整段为主，不靠替换几个近义词完成。

## 四、写作和验证怎样分配时间

- **10% 先把标准讲清**：读本文件、`outline.md` 和 [`prose-standard.md`](./prose-standard.md)，确认这一章要完成什么。
- **10% 把证据找齐**：优先使用公开研究索引和私有案例库；内部案例不能成为唯一证据。
- **80% 用在写作、验证和修订**：先写一页纸，确认论证走得通，再展开成章；改一节之前，先知道它在全书里做什么，然后按 prose standard 重写。

章节状态：`一页纸 → 展开中 → 完稿 → 持续公开修订`。

## 五、怎样判断它有没有真的发生作用

长期看三件事：核心概念是否成为组织语言；有多少团队用书里的标准完成第一轮改造；Regenic.ai 是否持续公开可复查的成功、失败和适用条件。
